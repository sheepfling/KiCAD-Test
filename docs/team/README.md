# Team documentation

This is the adopter-owned home for durable documentation that applies across
multiple boards or products. Add folders only when real material needs them, and
link every new Markdown page from this README so the documentation gate can find it.

Good candidates include system context, accepted architecture decisions, team roles,
approved tool sources, lab procedures, and organization-specific release retention.
Keep a board decision with that board in `projects/<id>/docs/`; keep product assembly
and integration decisions in `products/<id>/docs/`.

Use an issue or pull request for proposals and investigations. Keep test-run output
in CI artifacts or ignored `build/` directories. Once a decision becomes stable,
write the outcome and rationale here without copying the temporary work log.
